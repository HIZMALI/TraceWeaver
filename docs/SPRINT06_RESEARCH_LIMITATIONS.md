# Research limits and a future fair comparison

The previous `evaluation/graph-vs-flat` study, all source files, both raw result generations,
fourteen questions and R13 erratum remain unchanged. This sprint does not run a replacement
benchmark or claim a graph accuracy/runtime win. In that small corpus, lexical retrieval was
much faster. The arms received different task knowledge: structured native intent versus text
retrieval. The result is an illustrative retrieval exercise, not evidence of superiority.

R13 assumes a source cap ordering that the preserved engine never promised. Source candidate
LIMIT applies to ID/target ordering before later returned-subset temporal sorting. The existing
erratum retains the failed raw comparison; it must accompany any historical discussion. Do not
repeat its raw exact-set total in submission marketing.

Sprint 06 adds real native tool execution and proof admission, not a fair graph-versus-flat
experiment. Its frozen 35 cases use explicit fixture identities and safety policy; its metrics
measure those synthetic expectations. No independent production labels, blinded adjudication,
source authentication, model accuracy distribution or causal inference is available. A single
genuine model tool call is runtime evidence, not a percentage. The optional Ollama final admission
remains unverified successfully in this session.

A future preregistered experiment should give both arms identical typed node/edge facts, exact
incident anchors, options, depth, ordering and caps. A flat-table join baseline must receive the
same task schema and preserve relationship directions; BM25 alone is not that baseline. Freeze
answer sets, path schema, unknown/abstention labels and adversarial cases before execution.
Measure complete directed-path validity, returned scope, bounded omissions, implementation and
audit complexity, and separately measured warm/cold runtime/memory. Include negative controls,
uncertainty and sample counts. Report equality when both formulations express the same joins.
Do not tune ranking/caps after observing gold. Native row limits bound returned output, not engine
RAM or full query work. No such new fair comparator was established in this sprint.
